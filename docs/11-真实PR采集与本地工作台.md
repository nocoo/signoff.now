# 11 — 真实 PR 采集与本地工作台

> 当前实现：共享监控清单与显式发现。完整架构见 [14](14-collector-architecture.md)，命令和返回值见 [18](18-cli-query-contract.md)。早期“自动发现 + 刷新当前页”已由本实现替代。

## 启动

从仓库根目录分别运行：

```bash
bun install --frozen-lockfile
bun run dev:worker
bun run dev
bun run signoff daemon
```

Worker 为 `http://127.0.0.1:37042`，Web 开发端口为 7042，本机代理可使用 `https://signoff.dev.hexly.ai`。`dev:worker` 先应用本地 D1 迁移。启动时不会重置数据库或自动添加监控项；0019 升级保留旧快照，新的监控清单为空。

daemon 只在领取到真实 ADO 任务后创建 provider 并检查登录。已有缓存的查询和空清单运行不需要 Azure CLI。实际采集使用 `az account get-access-token`，需要有权访问项目的 Azure 登录：

```bash
az login --scope 499b84ac-1321-427f-aa17-267ca6975798/.default
```

有效令牌会复用，接近过期会续期；401 会重新取令牌重试一次。交互登录失效时任务显示 `auth_required`，项目按 15–60 秒退避，不影响另一项目或缓存查询。403 与认证过期分别处理。

## 从候选到监控

网页：Projects 添加组织、项目与仓库范围 → Pull requests 点击 Discover PRs → 查看候选（默认不含 Draft）→ 勾选并点击 Add to watch list。表头只全选当前页，支持批量移除；Watch list filter 可查看全部、监控中、未监控。

CLI 使用相同接口和同一份清单：

```bash
bun run signoff repo add 'https://dev.azure.com/acme/Platform/_git/web-app'
bun run signoff discover --repo 'https://dev.azure.com/acme/Platform/_git/web-app'
# 用上一步返回的 job ID 检查执行结果
bun run signoff job get '<job-id>'
bun run signoff pr list --repo 'https://dev.azure.com/acme/Platform/_git/web-app' --state all --draft include --all
bun run signoff watch add 'https://dev.azure.com/acme/Platform/_git/web-app/pullrequest/42'
bun run signoff watch list --all
bun run signoff refresh --all
bun run signoff watch remove 'https://dev.azure.com/acme/Platform/_git/web-app/pullrequest/42'
```

注册不等于发现，发现不等于监控。发现完整枚举可访问 PR 历史，包括 Draft / Completed / Abandoned，不逐个读取 builds / stages。仓库目录解析成功后，可用完整 URL 加入尚未取得快照的 PR；此时 watch list 显示待首次结果。已缓存终态不能重新监控。

## 调度、发布与错误

- 每项目同时一个任务，最多两个项目并行。检查只覆盖 active 监控项，默认整轮完成后等待 5 分钟；可以设置为 Manual，仅执行明确请求的刷新。
- 发现没有定时器，只处理明确提交的任务。同项目发现期间，后续 PR 状态任务等待它完成。
- 单个任务租约 120 秒，执行器每 20 秒续租与心跳。进程退出或崩溃后，其他执行器可在租约过期后重新领取；仓库计划保持不变。
- 每仓库先暂存，数量与版本校验通过后原子发布。采集中的 staging 不会出现在查询结果里。
- 只有明确终态可自动退出监控；404、403、缺席、网络失败和 Azure 登录过期保留监控项。普通失败结束本次尝试，下一自动轮次或显式刷新继续；认证失败保留任务并退避重试。
- 快照、任务、配置和清单均在本地 Wrangler SQLite / D1；Activity artifacts 与生产 pipeline token 不参与本机工作台。

`workbench watch` 是 `daemon` 的兼容别名。`workbench sync [--repo <urls...>]` 现在只注册并提交发现，立即返回任务回执，不再同步采集全部 PR 检查。`/api/collection/view` 返回 410，旧页面范围不能继续驱动采集。

## 验证

`bun run test:coverage` 覆盖域逻辑、SQLite、HTTP、CLI 子进程和网页状态机；`bun run test:e2e` 启动独立 Wrangler D1 与浏览器，验证完整迁移、发现、网页 / CLI 清单共享、Draft、并发删除保护、失败保留旧数据、来源切换和终态淘汰。E2E provider 注入仅存在于测试边界，没有产品 mock 开关。

不要在日常数据库运行旧 `scripts/e2e-06-local.sh`。本次系统测试在临时目录中创建带所有权标记的状态，结束后清理自己创建的进程与数据库，不触碰日常 `.wrangler/state`。
