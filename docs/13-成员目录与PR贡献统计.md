# 13 — 成员目录与 PR 贡献统计

> 本文记录已实现功能。后续[观察列表方案](14-collector-architecture.md)只改变持续采集范围；统计仍覆盖已经保存的 PR 快照，按显式筛选手动计算。

Directory、Repos 和 Insights 使用统一的 `projects` / `pull_requests` 数据，与全局 Live / Sample 同步。ADO 真实采集和 GitHub 示例走相同契约；真实 GitHub CLI 接入仍属于后续阶段。

## 页面与身份

| 页面 | 路径 | 用途 |
| --- | --- | --- |
| Repos | `/repos` | 按组织、项目、仓库和贡献者比较已采集 PR，跳转源仓库或 PR 队列 |
| Members | `/developers` | 发现真实 PR 作者、关注成员、关联账号、编辑团队和标签 |
| Teams / Tags | `/teams`、`/tags` | 管理成员所属关系和筛选标签，跳转对应贡献统计 |
| Contributions | `/insights` | 指定日期、项目、仓库、成员、团队、标签、PR 状态的贡献统计 |

侧栏 Workspace 中 Repos 位于 Projects 上方。页面使用 Basalt PageHeader、顶栏面包屑、表格和多选控件；图表使用 Recharts 与 Basalt ChartFrame、图例和提示框。旧 Activity 页面重定向到 Contributions；旧 Activity / Score API 和 CLI 保留独立契约。

成员沿用 `developers` 表，团队和标签沿用 `teams` / `tags`，新增 `source` 将 Live 和 Sample 隔离。`developer_identities` 保存显式账号关联，账号键为 `[provider, lower(organization), actorId]` 的 JSON 数组。一个账号只能属于一个成员；不同组织或 provider 的账号可由用户明确归属到同一成员。不通过同名、邮箱别名或旧 activity alias 猜测归属。ADO 作者保留 CLI 取得的 `uniqueName` 作为可搜索账号信息。

成员、团队、标签支持新增、编辑、归档、恢复；归档成员的账号关联保留。统计全部作者时，已归档成员以未关注账号计数；仅关注成员的筛选排除已归档成员。归档条目的贡献入口在恢复后重新显示。无匹配 PR 的活跃关注成员仍可出现在成员明细中，数量为零。

归档条目的成员关系保持休眠，编辑其他活跃条目时不会删除这些不可见关系；恢复后重新显示。目录响应带来源独立的 `revision`，写请求通过 `If-Match: "<revision>"` 提交打开编辑器时的版本。成员、团队、标签和账号关联的修改，包括旧接口写入，都会推进对应来源版本；过期保存返回 409，并回滚整个批次。页面保留未保存草稿，提示重新加载目录并重新打开编辑器。

## 统计口径与刷新

Contributions 默认最近 30 个 UTC 自然日，日期两端均包含，最多 366 天。Repos 默认统计全部已记录日期。日期按 **PR 创建时间** 筛选，Open / Merged / Closed 表示该批 PR 的**当前状态**；Merged 不表示期间发生了多少次合并。默认不含 Draft；包含时 Draft 为独立类别，四类合计等于总数。

统计 SQL 覆盖全部已存储 PR，不受工作台 1,000 条读取上限影响。团队和标签用存在性筛选，跨多个团队不重复计算同一 PR。统计依然受采集历史范围限制：List 采集全部开放 PR，以及每仓库最近最多 20 条 merged、10 条 closed；已知开放 PR 会继续对账到终态。未曾采集的旧 PR 不会自动补齐。

仓库名称、未关注作者姓名和头像选自同一来源下该身份最新的观测记录，不受日期筛选影响；关注成员的自定义姓名和头像优先。数量与采集时间仍只统计筛选范围内的 PR。

PR overview、Creation trend、Member contributions、Repository contributions 和 Repos overview 各有独立 Calculate / Refresh 按钮。

- 进入页面、改变筛选、切换来源只读取已保存计算，不触发重算。
- 点击按钮只计算该模块和筛选范围，使用数据库已有记录，不额外请求 ADO 历史。
- 计算结果及 `calculatedAt` 保存在 `pr_stat_snapshots`，按 source、module 和规范化筛选隔离。
- 数据库先分配递增刷新轮次，再以该轮次检查发布资格；同毫秒请求和时钟回退也不能让旧结果覆盖新轮次。失败保留上次成功结果。
- 超过 24 小时标黄，超过 72 小时标红；时间恰好等于边界时仍保持前一等级。
- 时间提示使用分钟粒度，例如 `< 1 min ago`、`3 min ago`。本地计时更新文案和颜色，不发起采集或重算。

PR 列表的 **PR updated** 为源 PR 自身更新时间，**Synced** 为 SignOff 最近取得基础数据的时间；已有检查快照另列 **Checks synced**。它们与统计模块的计算时间分别显示。组织、项目、仓库、PR 编号和标题旁链接均可打开相应源页面。

筛选保存在 localStorage，Insights、Repos、Directory 按页面及 source 隔离。成员、团队、标签的 Contributions 链接保留当前日期，清除无关实体及仓库范围；应用链接参数后消费一次，避免之后切换 Live / Sample 时重用旧来源的成员 ID。

## 接口与本地初始化

| 方法 | 接口 | 行为 |
| --- | --- | --- |
| GET | `/api/directory?source=cli\|demo` | 成员、团队、标签、精确作者账号和仓库目录 |
| POST / PUT | `/api/directory/:kind[/:id]?source=…` | 新建 / 完整保存 members、teams、tags |
| POST | `/api/directory/:kind/:id/archive`、`restore`，带 source | 归档 / 恢复 |
| GET | `/api/insights/:module?filters=<JSON>` | 只读取该模块已有计算，无缓存返回 null |
| POST | `/api/insights/:module`，body 为 filters | 重新计算并保存该模块 |

接口保持原有 Access / machine-token 边界。Sample 编辑和统计计算仅允许本地 demo 模式；已保存的 Sample 统计可只读查询。身份唯一约束、成员关系外键、source 触发器和目录版本检查保护批量写入，冲突回滚整个 D1 batch。

本地迁移为 `0017_pr_directory_and_statistics.sql` 和 `0018_directory_revisions.sql`，`dev:worker` 启动时会自动应用。新环境运行 `bun run db:seed:local` 同时初始化示例 PR 和成员关系。现有环境只需增加 Sample 目录时运行：

```bash
bun run db:migrate:local
bun run db:seed:local --directory-only
```

该选项不重建项目、PR 或已有 Readiness / refresh 设置。示例包含 6 个关注成员、3 个重叠团队、3 个标签，保留未关注作者供发现功能演示；不会编造真实团队归属。

## 验证

域模型与实际 SQLite 测试覆盖精确账号唯一性、跨来源隔离、成员关系双向编辑、独立数据库连接并发保存冲突、旧接口编辑失效保护、并发账号抢占回滚、归档关系恢复、重复团队去重、UTC 日期边界、Draft / 状态过滤、超过 1,000 条 PR、最新名称和头像、同毫秒计算发布顺序、模块缓存隔离和失败保留。前端测试覆盖手动计算生命周期、迟到响应隔离、筛选缓存、编辑器原始版本、外链和分钟计时。

浏览器验收使用本地真实 Worker / SQLite，验证两个真实 ADO 仓库、Sample 目录、成员贡献跳转和团队关系保存；另用隔离夹具检查分页与 24h / 72h 颜色边界。320–1440px 无页面横向溢出；表格在窄屏内独立滚动。
